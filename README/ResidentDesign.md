# 월계1동 주민을 위한 모바일 홈 디자인

## 방향

**가까운 가게의 소식을 발견하고, 위치를 확인하고, 문의하는 동네 생활 화면.**

네이버지도에서 참고한 것은 지도와 피드를 오가는 사용 방식이다. 화면의 색, 문구, 게시글 구성은 월월계계의 동네 상권 서비스에 맞춘다. 점수를 보장하는 디자인은 없지만, 제공된 대회 평가표의 실현·상용화 가능성 30점과 지역 문제 적합성 20점을 고려하면 장식보다 실제 이용 흐름을 설득력 있게 보여주는 것이 중요하다.

## 이번 로컬 시안

- 따뜻한 아이보리 바탕, 기존 브랜드와 연결되는 자주색, 동네 지도의 녹색을 사용한다.
- 첫 화면은 사장님 소식이 중심이다. 소개 문구는 짧게, 게시글 제목은 사진보다 먼저 보여준다.
- 공간 빌리기·하루 배우기·마감 할인·스탬프 모으기로 주민의 목적을 바로 안내한다.
- 게시글에 가게명, 제목, 가격 단위, 이용 시간 또는 수업일, 문의 가능 상태, 위치를 표시한다.
- 검색, 종류별 보기, 찜한 가게의 소식 모아보기를 제공한다. 새 데이터 규격을 만들지 않고 기존 소스와 공통 가게 찜 기능을 재사용한다.
- 손잡이는 드래그·클릭·키보드 위아래 방향키로 조작할 수 있다. 게시글 자체를 스크롤하는 동작과 지도 크기를 바꾸는 동작을 분리한다.
- 게시글의 지도 보기 버튼은 해당 가게를 선택한다. 피드로 돌아오면 검색·분류와 읽던 위치를 유지한다.
- 주요 조작 버튼은 44px 이상을 확보하고, 키보드 포커스와 동작 상태를 표시한다. 하단 내비게이션과 기존 카테고리 설정은 유지한다.
- 가로로 넓은 화면에서는 피드를 왼쪽 패널로 배치한다. 모바일이 기준이고 PC는 보조다.

## 코드 경계

### 동네 지도 조작 (2026-09-27)

- 월계1동 주변의 기존 탐색 시작점을 유지하고 확대 단계를 2~5로 제한한다. 기본은 4이며, 숫자가 작을수록 확대된다.
- 이동 자체는 막지 않는다. 기준점에서 1.5km 넘게 이동하면 동네 복귀를 안내한다. 이 거리는 행정동 경계가 아닌 UX 안내 기준이다.
- `＋ / −`는 각각 48px 터치 영역을 확보하고 한계에서 비활성화한다. 실제 SDK의 두 손가락 조작도 같은 확대 제한을 사용한다.
- `월계1동으로`는 중심과 확대 크기를 함께 초기화한다. GPS 현재 위치 버튼으로 오해하지 않도록 이름을 명시한다.
- 피드가 접혔을 때 패널 높이를 줄여 지도 공간을 확보하고, 작은 화면의 선택 가게 정보는 독립 스크롤한다.
- 정확한 월계1동 행정 경계 데이터가 준비되면 가게 노출 범위를 별도로 정한다. 현재는 임의 경계선이나 강제 이동 제한을 추가하지 않는다.
- `mapArea.ts`에 중심/확대 제한/복귀 안내 거리를 모았고, `MapControls.tsx`는 실제 지도와 로컬 도식이 공유한다.

지도 확대 API: [카카오맵 공식 문서](https://apis.map.kakao.com/web/documentation/#Map_setLevel).

### 구성 파일

- `frontend/src/features/recommend/RecommendPage.tsx`: 피드·지도 상태, 선택 가게, 손잡이 드래그
- `HomeScreen.tsx`: 기존 소스에서 소식 조회, 검색·분류, 바로가기
- `FeedPostCard.tsx`: 주민이 읽는 게시글 카드와 가게 찜·지도 연결
- `FeedArtwork.tsx`: 사진 없는 게시글의 설명용 SVG 일러스트
- `NearbyScreen.tsx`: 지도 분류와 선택한 가게 안내
- `KakaoMap.tsx`: 실제 카카오 SDK 로딩과 마커 연결
- `MapPreview.tsx`: 키가 없는 개발 환경에서만 사용하는 배치 도식
- `recommend.css`: 홈 전용 반응형 스타일

공통 테마와 헤더·내비게이션 아이콘만 함께 다듬었다. 다른 팀원의 카테고리 폴더, 데이터 타입, DB 계층, 배포 설정은 바꾸지 않는다.

## 실제 서비스와 구분할 점

- 현재 소식에는 예시 데이터가 포함되어 있다. 운영 가게·모집 상태로 오해하지 않도록 예시임을 표시한다.
- 직접 작성한 글과 찜은 현재 브라우저에 저장된다. 실제 사장님 인증, DB 저장, 예약·결제는 이 디자인 작업의 범위가 아니다.
- 카카오 JavaScript 키가 설정되어 있으면 기존 실제 SDK를 사용한다.
- 키가 없는 로컬 개발 모드에서만 대표 예시 가게를 도식으로 표시한다. 이 도식은 실제 위치·도로·길찾기가 아니다. 운영 빌드에는 이 대체 지도를 노출하지 않는다.
- 거리 수치는 실제 사용자의 위치가 아닌 예시 기준점과 예시 가게 좌표 사이의 직선거리다.

## 발표 시 보여줄 흐름

1. “월계1동 주민이 오늘 동네에서 할 일을 찾습니다.”
2. `도자기` 검색 → 수업 소식과 가격 확인 → 가게 찜
3. 지도에서 보기 → 선택한 가게 확인 → 피드로 복귀
4. 게시글 상세 → 기존 전화 문의 안내 확인
5. 사장님 글쓰기 화면을 소개하며 실제 DB·인증 연결 전후를 명확히 설명

실제 지도 시연 전에는 로컬 SDK 도메인과 환경변수를 연결하고 실제 카카오맵에서도 선택·이동 동작을 별도로 검증한다.

## 로컬 검증

- TypeScript 검사와 Vite 프로덕션 빌드
- 모바일 390×844, 작은 화면 320×640, 가로 화면 844×390, PC 1280×900 확인
- 검색 결과 및 빈 결과, 가게 찜과 찜 분류, 게시글→지도 선택, 지도 분류 유지, 손잡이 드래그 확인
- 기존 원데이클래스 상세 화면 및 전화 문의 안내로 연결 확인
- 실제 카카오 SDK 호출은 로컬 키 미설정으로 미검증

이 시안은 로컬 비교용이며, 별도의 요청 전에는 커밋·원격 푸시·배포하지 않는다.
