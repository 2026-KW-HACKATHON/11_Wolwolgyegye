# 코드 작성

코드 작성 간에 다음 규칙을 따른다.

1. 웹/앱

- **이 프로젝트의 주 사용자는 모바일 사용자다. 화면은 모바일 세로 모드를 기준으로 먼저 설계하고 구현한다.** PC 화면은 모바일 흐름을 완성한 뒤 확장한다.
- 지도 화면도 모바일에서 가게를 찾고 선택하는 흐름을 우선한다.
- 주요 버튼은 손가락으로 누르기 쉽게 만들고, 작은 화면에서 가로 스크롤 없이 지도·카테고리·가게 상세를 이용할 수 있는지 확인한다.
- 웹 관련 언어 `HTML + CSS + JAVASCRIPT` 로 프런트를 다루지만,  
모바일(ios, 안드로이드)와 PC는 근본적으로 차이가 있다.
- 단순히 CSS를 `px`단위와, `%`단위의 차이로 구분하여 다룰 수 있겠지만,  
세로가 긴 모바일과 가로가 긴 PC는 그 차이가 명확하다 볼 수 있다.
- 이를 넘어서, 손가락을 이용한 터치와 마우스를 활용한 클릭은 엄연한 차이가 존재하므로,  
`내용은 같게`하되, `구현의 방식은 다르게` 구현한다.
- 다음과 같은 5가지의 상황들을 고려한다.
    - 모바일 (ios, 안드로이드) 가로모드
    - 모바일 (ios, 안드로이드) 세로모드
    - 태블릿 (ios, 안드로이드) 가로모드
    - 태블릿 (ios, 안드로이드) 세로모드
    - PC (데스크탑, 노트북 등)
---
2. 작업 구조

- `Base.md`에서 사전에 명명한대로, 순서도에서 카테고리라는 커다란 틀 내에서  
여러가지 하위 목록들이 존재하고 하나하나 전부 객체로 가정하여 각자 구현한다.
- 이때, 객체로 구현하기에 서로 간에 상호작용할 인자에는 미리 선언할 이유가 없지만,  
공통적으로 활용하는 `데이터 셋`은 그 이름을 통일하고 미리 합의해야한다.
---
3. 테마
- 이후 `설정`에서 통합적으로 바꿀 수 있음을 감안하더라도,  
`CSS를 통한 색상 지정 하드코딩`을 지양하고 `특정 키워드로 선언해두는 것으로` 함.
- 나중을 위한 과정이니 참고 바람.

4. 카테고리 폴더 형식

- 가게 공통 정보(이름, 위치, 주소, 영업시간, 별점 등)는 `core/types/place.ts`의 `Store` **한 곳에만** 둔다.  
카테고리 데이터에 가게 이름/업종/거리를 복사해 넣지 않고, `storeId`로 참조한다.
- `features/<카테고리>/` 안의 파일 이름은 아래로 통일한다.

| 파일 | 역할 |
| --- | --- |
| `index.ts` | `export { default } from './XxxPage'` |
| `XxxPage.tsx` / `xxx.css` | 화면 |
| `types.ts` | 이 카테고리의 데이터 규격 (= DB 테이블 한 행). `XxxView` = 행 + `store` (+ `walkMinutes`) |
| `source.ts` | 데이터 조회 지점. 화면은 이 함수만 부르고, DB 조회는 이 파일 안에만 둔다 |
| `constants.ts` | 화면 전용 상수 (정렬 옵션, 색, 프리셋 등). DB와 무관한 것만 |

- 비율 값은 `0 ~ 1` 소수로 저장한다 (예: 할인 30% → `0.3`). 표시할 때만 `%`로 바꾼다.
- 도보 시간·할인가처럼 계산 가능한 값은 저장하지 않고 `source.ts`/유틸에서 계산한다.
- 카드 색 같은 표시 규칙은 데이터에 넣지 않고 `constants.ts`에서 정한다.
